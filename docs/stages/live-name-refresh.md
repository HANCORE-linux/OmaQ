# Live name refresh

The helper saves a profile nickname before sending it to every existing native Tox group through `tox_group_self_set_name()`. Group broadcasts are not an atomic cross-peer transaction: a send failure can occur after the local group name changes. The saved profile remains authoritative; an incomplete group send or save projects that profile without a success acknowledgement, then returns the request-correlated `nickname_group_sync_failed` warning. An explicit same-name retry sends again. A profile-save failure does not begin group updates, and uncertain primary publication retains the existing fail-closed identity guard.

Tox friend-name callbacks run before the native friend-name getters change. The helper coalesces their notifications and emits a fresh bounded Friends projection immediately after Tox iteration. Group peer-name callbacks refresh the Groups projection. Open DirectChat headers, GroupChat member rows, message and search sender labels, and typing labels read these projections reactively. No panel refresh, shell restart, or name-polling path is required.

The C regression covers all existing groups, sparse native group numbers, still-joining groups omitted from Tox's initialized-group count, the group-count bound, invalid input, partial sends, same-name retries, and save failures. A network-disabled helper IPC test injects native send/save failures and checks published profile state, actual event ordering, correlation, retries, and fail-closed identity shutdown. Phase 3 changes names in both directions between two connected helpers after group creation and acceptance; it requires unsolicited Direct and Group projections without status/list requests or another message. Offscreen QML fixtures cover name reactivity and correlated partial-result feedback. These automated checks do not replace native acceptance.
